# small_daily

记录每一天的日程时间，看得见的统计图表，还有每天 / 每周的计划进度。

本地优先（数据只存在你自己的浏览器里，**永不自动清除**）、离线可用（Service Worker 缓存应用外壳）、移动端优先（底部导航 + 底部抽屉，单手可用）。

线上地址：<https://calcury.github.io/small_daily/>

---

## 功能

**界面**

- **无卡片风格**：内容区块不用带边框 / 阴影的卡片盒，而是用一条细分隔线 + 留白分段；KPI、状态等并列信息用竖线分隔。
- 顶部日期导航只在**「今日」**出现（统计 / 计划 / 设置 三页的日期不参与任何计算，所以不显示）。

**记录**

- **当前状态卡** — 主界面顶部显示此刻正在做的事、已持续多久；点一下就能切换状态，还能把切换时刻往前调（比如补记 9:00 就该开始工作了）。
- **24 小时时间轴** — 一整天被涂成一条彩色带。**点一下任意位置就能改那一段**（按坐标命中，很窄的时段也点得中）。
- **昨日对照轴** — 主时间轴上方还有一条更细的条，画的是昨天（看历史日期时是它的前一天）的状态分布，用来对照。
- **计划进度** — 按状态展示「今天」和「本周」的目标完成情况（进度条 + 已完成打勾），取代了原先「今天 vs 昨天」的状态进度条。

**编辑任意时间段**

- 点时间轴上的任意一段 → 打开编辑器，里面是**两条可以左右滑动的分界线**：按住左边那条拖动改开始时间，按住右边那条拖动改结束时间。
- **今天只能改到「此刻」为止**（还没发生的事不能记），此刻之后的区域**一律留白**；**昨天及更早**则整天都能随便改。**明天及以后**根本浏览不过去，日期导航和日历都到今天就封顶。
- 点**灰色的「空」**也是一样的：直接把整段「空」当作事件选中，一样能拖分界线改长度、改状态，不会凭空塞一个短事件进去。
- 拖动会吸附到 **5 分钟**，也支持键盘方向键微调（按住 Shift 步进 15 分钟）。背景用**和正常一致的颜色**画出当天的其它时段，方便一眼看出会盖住谁；正在编辑的那一段在背景里先按「空」占位，所以拖动时能实时看到挖空 / 覆盖的效果。
- 两条线贴在一起（很短的时段）也分得开：命中判定是「离哪条线更近就拖哪条」。
- 拖动分界线**会覆盖经过的其它时段**；把彩色时段拖短，空出来的部分会自动变回「无」，这个灰色空洞同样可以点开再指定成别的状态。
- 有色的也可以改回「无」（状态类型里直接选「无」即可）。也可以直接在「添加时段」里新建一段。
- 所有编辑都会**自动合并**相邻的同状态时段，时间轴永远无缝铺满 0:00–24:00。

**找某一天**

- 头部左右两个箭头翻前一天 / 后一天。
- 点中间的日期可以打开**日历**，按月份浏览、选一天进入；有记录的日子会带一个小圆点。未来（今天之后）在日历里是禁用的。
- 看历史日期时，头部会出现**「回到今天」**。

**自定义状态**

- 内置：睡觉 / 工作 / 学习 / 娱乐 / 休息 / 运动，外加不可删除的「无」。
- 可以新建、改名（内联编辑）、用 20 色色板或系统取色器改色、上下排序、删除（删除后历史记录里的该状态退回「无」，不丢数据）。

**计划**

- 底部导航的**「计划」**页里，给任意状态定**每天**要做到多少小时、**每周**总共多少小时（一个状态最多一条计划）。输入留空 / 0 就是「不设」。
- 「今日」页的**计划进度**会按状态列出「今天」与「本周」的完成情况；达到了目标会打勾。本周按**周一起**统计，看历史日期时统计到那一天为止。
- 计划跟着数据一起存、一起导入导出，和记录一样不会自动清除。

**统计图表**

- 近 7 / 14 / 30 天**趋势曲线**（可切换成**堆叠柱状图**），点任意一天可以看那天的详情。
- 当日**环形图**（各状态占比）+ 图例。
- **时长排行**条形图。
- **每日明细**列表，每天一条堆叠占比条。
- KPI：日均记录时长、有记录的天数、投入最多的状态。

**数据安全**

- 每次改动立即写入 `localStorage`，带「上一版本备份」自动轮转，JSON 损坏时可自动回滚。
- 「设置 → 数据」里可以**导出数据 / 导入数据**（导出文件名是 `small_daily-YYYY-MM-DD.json`）。
- **清空全部数据**会先弹窗确认（确定 / 取消），且清空前自动留一份备份。

**更新版本**

- 「设置 → 版本」显示当前页面的构建时刻，提供**「更新版本」**按钮：一键清掉本应用的外壳缓存、注销 Service Worker，再带缓存击穿参数重新拉取整份页面资源。
- 这一步**只释放资源、不动记录** —— 日程数据都存在 `localStorage` 里，更新后照旧。
- 状态栏里带出来的 `?v=<时间戳>` 会在新页面启动时自动抹掉，不会留在地址栏或分享链接里。

## 本地开发

需要 Node 18 及以上（开发时用的是 Node 22）。

```bash
npm install        # 安装依赖
npm run dev        # 启动开发服务器 → http://localhost:5173/
```

想在手机上试（同一局域网内）：

```bash
npm run dev:host   # 会额外打印一个局域网地址，用手机浏览器打开即可
```

> 开发模式下 `base` 是 `/`，所以直接访问 `http://localhost:5173/` 就行，不用带子路径。

### 本地验证生产构建

```bash
npm run build      # 类型检查 + 打包到 dist/
npm run preview    # 用 dist/ 起一个本地静态服务 → http://localhost:4173/small_daily/
```

`preview` 会按生产环境处理 `base`，所以地址里要带 `/small_daily/`，和线上保持一致。

### 其它命令

```bash
npm run typecheck    # 只做类型检查
npm run check        # 区段编辑逻辑自检（含 400 次随机编辑的模糊测试）
npm run check:deploy # 校验构建产物有没有跑到站点根路径上去（见下文「路径约定」）
```

`npm run check` 验证的是整个应用最核心的不变式：任何时候时间段都无缝铺满 0:00–24:00、相邻同状态自动合并、清空留出的空洞能重新涂色。

`scripts/shoot.mjs` 是渲染 + 真交互的验证脚本（无头 Chrome + DevTools 协议，真实鼠标事件，顺带出图到 `.preview/`）。它会把「此刻」固定成 19:25、注入一份可预期的数据，然后跑满整套断言（共 87 条）：时间轴未来留白、编辑器的拖动与边界、日历与回到今天、计划页的新增 / 修改 / 删除与首页进度（含达成打勾）、无卡片风格与各页顶部日期、数据面板的弹窗确认，以及**「退出再进 / 彻底断网后重进，记录依然在」**。用法：

```bash
npm run build && npm run preview     # 另开一个终端
node scripts/shoot.mjs
APP_URL="https://calcury.github.io/small_daily/" node scripts/shoot.mjs   # 也可以直接对线上跑
```

## 部署到 GitHub Pages（CI 自动）

仓库里已经配好 `.github/workflows/deploy.yml`：**推到 `main` 分支就自动构建并发布**。

### 一次性设置

在仓库页面进入 **Settings → Pages**，把 **Build and deployment → Source** 设成 **GitHub Actions**。

> ⚠️ **这一步必须手动做，工作流改不了它。** `GITHUB_TOKEN` 即使带 `pages: write`，把 legacy 站点切到 workflow 时也会返回 `403`（只有仓库管理员的 PAT 才有权限）。
>
> 工作流里的「校验 Pages 来源为 GitHub Actions」这一步会**读取**当前来源：不是 `workflow` 就直接报错，避免出现下面这种「CI 绿、线上却是旧的」的静默故障。若想让它自动纠正，可以在仓库里配置一个带 `repo` 权限的 secret `PAGES_ADMIN_TOKEN`。
>
> ⚠️ 如果这里停留在 **"Deploy from a branch"**，会出现很迷惑的现象：CI 显示成功，但线上打开是白屏、控制台一堆 404。原因是分支的**根目录被原样当站点发布**了，`index.html` 里的 `/src/main.tsx`、`/manifest.webmanifest` 这些都指向别处；同时 GitHub 自带的 `pages build and deployment` 工作流也会跑，和我们的部署互相覆盖。判断方法：`curl -s https://calcury.github.io/small_daily/assets/<打包文件名>` —— 如果 404，就是这个坑。

### 日常发布

```bash
git add -A
git commit -m "更新"
git push origin main
```

推送后在仓库的 **Actions** 标签页可以看到 `Deploy to GitHub Pages` 在跑；跑完访问 <https://calcury.github.io/small_daily/> 即可。也可以在 Actions 页面用 `Run workflow` 手动触发。

### 路径约定（重要：别和别的仓库打架）

本仓库是**项目站点**，发布在 `https://calcury.github.io/small_daily/` 这个**子路径**下；而 `calcury.github.io` 的**根目录属于另一个仓库**（用户站，比如 [calcury.github.io](https://github.com/calcury/calcury.github.io)）。

所以本仓库的产物里**不能出现任何指向根路径的引用**（`/small_daily.ico`、`/manifest.webmanifest`、`/sw.js` 这种）。一旦出现，浏览器会跑到根目录去取文件 —— 轻则 404，重则加载到别的仓库的内容；如果注册了根作用域的 Service Worker，还会反过来控制你所有的项目页。

约定如下：

- `vite.config.ts` 里生产环境的 `base` 固定为 `/small_daily/`。
- `index.html` 里引用 public 资源统一用 `%BASE_URL%` 前缀（构建时会替换成 `/small_daily/`），不要硬写 `/xxx`。
- Service Worker 用 `` `${import.meta.env.BASE_URL}sw.js` `` 注册，作用域自然收敛在 `/small_daily/` 内。
- `manifest.webmanifest` 内部一律用**相对路径**（`"src": "small_daily.ico"`、`"scope": "."`）。
- `npm run check:deploy` 会在 CI 里把守这条线：只要产物里出现根路径引用（或引用了不存在的文件），构建直接失败。

如果将来仓库改名，改 `vite.config.ts` 里的 `base`、`scripts/check-deploy-paths.mjs` 里的 `BASE`，以及 README 里的地址即可。

## 数据是怎么存的

- 位置：当前浏览器的 `localStorage`，键名 `small-daily:data:v1`。
- 策略：**没有过期时间，没有任何自动清理逻辑**。只有你自己清空数据，或者清除浏览器站点数据，才会消失。
- 备份：每次写入前会把上一个版本存到 `…:backup`，主数据损坏时自动回滚。
- 不上传：没有任何后端，数据不会离开这台设备。
- 建议：偶尔在「设置 → 数据」里点一次**导出数据**留个备份，尤其是换设备或清理浏览器之前。

> Service Worker 只缓存**应用外壳**（HTML/JS/CSS），缓存名前缀 `small_daily-shell-`，升级时只清理自己前缀的旧缓存，不碰用户数据和别的站点缓存。所以**断网也能打开**，记录照常读写。

## 技术栈

Vite 5 · React 18 · TypeScript（strict）· 手写 CSS · 手写 SVG 图表 · 原生 Service Worker。
无 UI 框架、无状态管理库、无图表库、无后端。
